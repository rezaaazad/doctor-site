# گزارش تحویل پروژه doctor-site.ir

تاریخ این گزارش: ۲۰ آبان ۱۴۰۵ / ۲۰ نوامبر ۲۰۲۶ (منطقه زمانی Asia/Tehran، UTC+3:30).  
مخاطب: برنامه‌نویسی که قرار است نگهداری یا توسعه را ادامه بدهد.  
منبع کد: کپی فقط‌خواندنی از `/opt/doctor-site` روی سرور تولید. روی سرور هیچ فایلی تغییر داده نشد، ری‌استارت نشد و چیزی پاک نشد.

## ۱. معرفی و استک

**دکتر سایت** سایت معرفی/آژانس فارسی برای خدمات طراحی سایت، برنامه‌نویسی، برندینگ و مارکتینگ/سئو است. دامنه عمومی: `https://doctor-site.ir` (و `www.doctor-site.ir`). ظاهر فعلی تیره‌رنگ (navy/black) با رنگ تأکیدی سبزlime (`#D6FF3F`)، هیرو WebGL، فونت‌های خودمیزبان، و یک پنل مدیریت سفارشی که تقریباً همه متن‌ها، قیمت‌ها، نمونه‌کارها و تنظیمات را بدون redeploy عوض می‌کند.

سایت زنده در زمان تهیه این گزارش پاسخ `HTTP/2 200` می‌دهد (از پشت CDN پارس‌پک / WCDN). پنل `/admin` بدون نشست به `/admin/login` ریدایرکت می‌شود (`307`). endpoint سلامت داخل اپ `{ "ok": true }` برمی‌گرداند.

## ۴. پنل ادمین

ورود: `/admin/login`. کوکی نشست: `ds_session` (httpOnly، SameSite=Lax، Secure روی HTTPS، اعتبار ۱۴ روز). توکن خام در کوکی است؛ در دیتابیس فقط SHA-256 توکن با pepper برابر `SESSION_SECRET` ذخیره می‌شود.

محدودیت ورود: ۸ تلاش ناموفق در ۱۵ دقیقه برای هر IP؛ تلاش‌های قدیمی‌تر از ۲۴ ساعت پاک می‌شوند. مقایسه رمز همیشه با یک هش ساختگی هم اجرا می‌شود تا زمان پاسخ برای ایمیل ناموجود لو نرود.

middleware فقط وجود کوکی را چک می‌کند و برای `/admin/*` هدر `X-Robots-Tag: noindex, nofollow` می‌گذارد. اعتبار واقعی نشست در `app/admin/(panel)/layout.tsx` با `getSessionUser()` بررسی می‌شود.

## ۶. API

API عمومی خیلی کوچک است. کار اصلی ادمین و فرم‌ها با Server Actions است.

| روش | مسیر | نقش |
| --- | --- | --- |
| `GET` | `/api/health` | `{ok:true}` بعد از `SELECT 1` روی Postgres؛ در غیر این صورت `503`. عمومی است و برای healthcheck کامپوز استفاده می‌شود. |

## ۷. سئو و آنالیتیکس

- متادیتا از `PageSeo` یا فیلدهای سئوی هر پست/پروژه/لندینگ؛ `metadataBase` از `SITE_URL`.
- canonical نسبی روی path، با `metadataBase` مطلق می‌شود. locale اوپن‌گراف: `fa_IR` با alternate `en_US`.
- تصویر پیش‌فرض OG در `app/opengraph-image.tsx` (۱۲۰۰×۶۳۰، وزیرمتن، جمله «ما کد می‌نویسیم، نه قالب»). اگر `ogImage` در سئوی صفحه خالی باشد همین تصویر پیش‌فرض استفاده می‌شود.
- JSON-LD سازمان روی همه صفحات عمومی؛ در لندینگ‌ها Breadcrumb + Service و در صورت وجود FAQ، `FAQPage`.
- `app/sitemap.ts` داینامیک است: مسیرهای ثابت + لندینگ‌ها + نمونه‌کارهای منتشر + پست‌های منتشر.
- `app/robots.ts`: اجازه همه، disallow برای `/admin` و `/api/`، اشاره به sitemap.
- `app/manifest.ts`: PWA ساده، `lang: fa`، `dir: rtl`.
- هدرهای امنیتی از `next.config.ts`: `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options: SAMEORIGIN`, `Permissions-Policy` (دوربین/میکروفن/موقعیت بسته)، `X-DNS-Prefetch-Control: off`. `X-Powered-By` خاموش است. Caddy هم HSTS با `max-age=15552000; includeSubDomains` و حذف هدر `Server` می‌گذارد.
- پنل با `robots: noindex` و هدر مربوطه.

نکته سئو: هم `doctor-site.ir` و هم `www.doctor-site.ir` خود صفحه را با `200` می‌دهند؛ در Caddy ریدایرکت www به apex (یا برعکس) نیست. خطر محتوای تکراری وجود دارد مگر روی کنسول جستجو یکی به‌عنوان دامنه اصلی تثبیت شود.

تقریباً همه layoutها `force-dynamic` هستند؛ صفحه خانه با `Cache-Control: private, no-cache, no-store` می‌آید. تصاویر Next `unoptimized` هستند (بهینهسازی ایمیج بیلد خاموش است).

آنالیتیکس: کامپوننت `Tracker` به `/api/track` پست می‌کند. هش بازدیدکننده روزانه از `SESSION_SECRET + تاریخ + IP + UA` ساخته می‌شود. IP در مسیر ترک، اولین مقدار `X-Forwarded-For` است؛ در لاگین/فرم تماس، آخرین مقدار. پشت CDN این دو ممکن است یکسان نباشند و آمار یا محدودیت نرخ را منحرف کنند. پاکسازی خودکار ردیف‌های قدیمی `PageView` وجود ندارد.

  - `doctor-site-caddy-1` (`caddy:2-alpine`) — پورت‌های میزبان ۸۰ و ۴۴۳؛ از حدود ۱۸ نوامبر ۱۴۰۵ / ۱۷ نوامبر ۲۰۲۶ ۲۲:۲۲ UTC بالا (بازسازی هنگام اضافه شدن وردپرس).
  - روی همان شبکه `doctor-site_default`: `wp-reza` و دیتابیس‌اش (`/opt/wp-reza` برای `reza.noorproxy.shop`). این پروژه جداست، ولی از همین Caddy سرو می‌شود.

Volumeها: `doctor-site_pgdata`، `doctor-site_uploads` (الان خالی)، `doctor-site_caddy-data`، `doctor-site_caddy-config`. آپلودها در کانتینر اپ روی `/data/uploads` هستند.

`docker-compose.yml` داخل ریپو هنوز سرویس یا شبکه وردپرس را اعلام نمی‌کند. در عمل کانتینر `wp-reza` به شبکه پیش‌فرض همین پروژه وصل شده و `Caddyfile` زنده این بلوک را دارد:

```
https://reza.noorproxy.shop { reverse_proxy wp-reza:80 }
```

**هر به‌روزرسانی Caddy یا `docker compose down` باید این وابستگی را در نظر بگیرد.** پایین آوردن پروژه یا ساخت دوباره شبکه `doctor-site_default` می‌تواند سایت وردپرس را هم قطع کند. `Caddyfile` را بدون بلوک `reza.noorproxy.shop` بازنویسی نکنید. بعد از ویرایش Caddyfile گاهی به‌خاطر inode بایندماونت باید سرویس caddy را recreate کرد (`docker compose up -d --force-recreate --no-deps caddy`) نه فقط `reload`.

### فایروال و CDN

سایت دکترسایت پشت CDN پارس‌پک است (هدرهای `server: WCDN ...`). پورت ۴۴۳ روی اینترفیس `eth0` فقط از رنج‌های مجاز باز است:

- اسکریپت: `/usr/local/sbin/centimelk-dockeruser-fw.sh`
- سرویس: `centimelk-dockeruser-fw.service` (اعمال در بوت و بعد از ری‌استارت داکر)
- فهرست CIDR: `/etc/centimelk/parspack-cdnips.txt` (۶۵ خط؛ از خط ۵۰ به بعد رنج‌های Cloudflare برای `reza.noorproxy.shop` اضافه شده، حدود ۱۵ رنج)
- زنجیر iptables: `CENTIMELK-CDN` روی `DOCKER-USER` برای tcp+udp و destination port اصلی ۴۴۳. غیر از این رنج‌ها DROP می‌شود (با لاگ محدود).
- پورت ۸۰ برای همه باز است (ریدایرکت HTTPS + ACME HTTP-01).
- Kill-switch: وجود فایل `/etc/centimelk/cdn-filter.disabled`. اگر فهرست CIDR خیلی کوتاه باشد فیلتر اعمال نمی‌شود (fail-open).
- اسکریپت همچنین دسترسی خارجی به پورت‌های قدیمی ۵۴۳۲۹ و ۶۳۷۹۹ را می‌بندد.

دکترسایت باید از طریق CDN پارس‌پک بیاید. Cloudflare روی این دامنه تنظیم نشده؛ رنج‌های Cloudflare فقط برای وردپرس همسایه است. ۴۴۳ را برای کل اینترنت باز نکنید مگر اینکه پیامدش را بدانید.

### متغیرهای محیطی (فقط نام)

از `.env.example`. مقادیر واقعی روی سرور در `/opt/doctor-site/.env` است و در این گزارش نمی‌آید.

- `POSTGRES_USER`
- `POSTGRES_PASSWORD`
- `POSTGRES_DB`
- `DATABASE_URL` (برای `npm run dev` محلی؛ داخل کانتینر اپ، Compose آن را با host=`db` می‌سازد)
- `ADMIN_EMAIL`
- `ADMIN_PASSWORD` (فقط برای ساخت اولین مدیر)
- `ADMIN_NAME`
- `SESSION_SECRET` (حداقل ۳۲ کاراکتر؛ چرخاندنش همه را خارج می‌کند)
- `SITE_URL`
- `UPLOAD_DIR`
- `HTTP_PORT`
- `HTTPS_PORT`
- `CADDY_EMAIL`
- `CADDYFILE`

اختیاری در کد: `SEED_ON_BOOT=0` برای نساختن سید در استارت.

اطلاعات ورود اولیه ادمین جداگانه در `/opt/doctor-site/ADMIN_CREDENTIALS.txt` روی سرور هست. این فایل را به git نبرید و در چت ننویسید.

### نحوه به‌روزرسانی (با احتیاط)

`DEPLOY.md` هنوز فرض می‌کند ریپوی git روی سرور است؛ الان نیست. روند پیشنهادی بعد از وصل شدن این ریپو:

1. روی سرور در `/opt/doctor-site` ریپو را clone/remote کنید، **بدون اینکه `.env` موجود overwrite شود**.
2. تغییرات را pull کنید.
3. `docker compose up -d --build` — این اپ را دوباره می‌سازد. volume دیتابیس و آپلود می‌مانند. entrypoint در استارت `prisma migrate deploy` می‌زند.
4. **Caddy را بی‌دلیل recreate نکنید** و `Caddyfile` را با نسخه‌ای که بلوک وردپرس ندارد جایگزین نکنید.
5. از `docker compose down` روی این پروژه برای «ریست معمولی» استفاده نکنید؛ شبکه مشترک و گواهی‌ها درگیر می‌شوند.
6. بیلد Next روی این ماشین کم‌رم است (سقف heap در Dockerfile برابر ۱۵۳۶MB و یک swap ۲ گیگ در `DEPLOY.md` آمده). هنگام بیلد بار سنگین دیگری نگذارید.

سلامت بعد از دیپلوی: `docker compose ps` و از خود سرور `curl -fsS http://127.0.0.1/api/health` (باید `{"ok":true}`). از بیرون: `https://doctor-site.ir`.

پیشنمایش محلی: Node 22 + Postgres 16، کپی `.env.example` به `.env`، `npx prisma migrate deploy`، `npm run dev` روی `http://127.0.0.1:43123`. یا Compose با پورت بالا و `CADDYFILE=./Caddyfile.preview`.

### پشتیبان

در `DEPLOY.md` دستور `pg_dump` و آرشیو volume آپلود نوشته شده، ولی روی سرور cron/timer خودکاری برای Postgres این پروژه پیدا نشد. تنها تایمر مرتبط سیستم، `dpkg-db-backup` اوبونتو است که به این دیتابیس مربوط نیست. **بک‌آپ منظم دیتابیس فعلاً وجود ندارد.**

## ۹. چیزهایی که ندارد / کارهای پیشنهادی (به ترتیب اولویت)

### بالا

1. **ریپوی git و مسیر دیپلوی مشخص.** تا امروز کد فقط روی دیسک سرور بوده، CI نیست، تست خودکار نیست (حتی یک فایل تست). این اسنپ‌شات برای ساخت ریپو آماده است. بعد از انتشار: remote روی سرور، قانون «`.env` هیچ‌وقت commit نشود»، و یک مسیر دیپلوی مکتوب که Caddy/وردپرس را خراب نکند.
2. **پشتیبان خودکار Postgres** (و در صورت پر شدن، volume آپلود). نگه داشتن چند نسخه روزانه/هفتگی بیرون از همین سرور.
3. **محتوای واقعی به‌جای سید.** نمونه‌کارها، نظرات، لوگو مشتری‌ها و بخشی از متن‌ها هنوز نمونه نمایشی‌اند. اطلاعات تماس و شبکه‌های اجتماعی باید واقعی شوند. لوگو و فاوآیکون آپلود نشده. اینماد خالی است.
4. **اطلاع‌رسانی پیام‌های فرم تماس** (ایمیل یا تلگرام به مدیر). الان لید فقط در پنل می‌ماند و اگر کسی پنل را باز نکند، پیام دیده نمی‌شود. خبرنامه هم فقط ذخیره می‌شود.

### متوسط

5. ریدایرکت یک‌دست `www` ↔ apex برای سئو.
6. اکشن حذف لندینگ، و بازبینی فاصله خالی‌های دیگر پنل.
7. محدودیت نرخ و بررسی مبدأ برای `/api/track`؛ یکدست کردن استخراج IP پشت CDN پارس‌پک؛ سیاست نگهداری/پاکسازی `PageView`.
8. پر کردن اینماد و (در صورت نیاز کسب‌وکار) درگاه پرداخت. الان هیچ پرداخت، سبد یا زرین‌پالی در کد نیست؛ قیمت‌ها فقط متن‌اند.
9. ترجمه EN را یا کامل کنید یا سوییچ را از سایت عمومی بردارید تا صفحه نیمه‌انگلیسی نماند.
10. هشدار و چک‌لیست «Caddy اشتراکی» را به `DEPLOY.md` اضافه کنید؛ سند فعلی از وردپرس همسایه و فایروال CDN حرفی نمی‌زند.

### پایین‌تر / کیفیت مهندسی

11. تست و lint در CI. الان `eslint.ignoreDuringBuilds = true` است و بیلد خطاهای lint را رد می‌کند.
12. بهینه‌سازی تصویر و کش بهتر برای صفحات عمدتاً ایستا (الان تقریباً همه‌چیز `force-dynamic` و no-store است).
13. مشاهده‌پذیری: آلارم روی healthcheck، لاگ متمرکز، نظارت دیسک/رم.
14. پوشه بازطراحی ردشده را برنگردانید مگر اینکه صاحب پروژه صریحاً بخواهد.

## ۱۰. نکات امنیتی

- اسرار را از `/opt/doctor-site/.env` و `/opt/doctor-site/ADMIN_CREDENTIALS.txt` بخوانید. در چت، تیکت یا git نگذارید. `.gitignore` فایل `.env` را نادیده می‌گیرد و `.env.example` را نگه می‌دارد.
- پوشه `/opt/doctor-site.bak-20261108-0226` هم `.env` و `ADMIN_CREDENTIALS.txt` دارد. آن را به ریپو کپی نکنید؛ دسترسی‌اش را محدود یا در جای امن آرشیو و از مسیر وب جدا کنید.
- `.env.example` و Dockerfile مقدارهای ساختگی دارند (`change-this-...` و آدرس بیلد `postgresql://doctor:doctor@127.0.0.1...` فقط برای `prisma generate`). این‌ها رمز پروداکشن نیستند. در `docker-compose.yml` اگر `.env` نباشد پسورد پیش‌فرض `doctor` استفاده می‌شود؛ روی سرور باید `.env` همیشه موجود باشد.
- اپ روی پورت ۳۰۰۰ میزبان publish نمی‌شود؛ فقط Caddy به بیرون گوش می‌دهد. Postgres هم پورت میزبان ندارد.
- فایروال ۴۴۳ را به CDN محدود کرده. دور زدنش سایت را مستقیم روی اینترنت می‌گذارد.
- آپلود تصویر: نوع MIME و جادوی فایل چک می‌شود؛ نام ذخیره تصادفی است؛ مسیر `/media` از directory traversal با الگوی نام جلوگیری می‌کند.
- `TrustHtml` در فوتر HTML اینماد را با `innerHTML` و اجرای اسکریپت تزریق می‌کند. فقط مدیر باید این فیلد را پر کند؛ اسکریپت شخص ثالث اینماد یعنی اعتماد به همان منبع.
- middleware به وجود کوکی بسنده می‌کند (نه اعتبار امضا). صفحه پنل نشست را کامل چک می‌کند، ولی این شکاف را در ذهن داشته باشید.
- فرم تماس و خبرنامه CSRF را با Origin چک می‌کنند. خبرنامه محدودیت نرخ ندارد.
- لاگ‌اوت و تغییر رمز، نشست‌ها را مدیریت می‌کنند. چرخاندن `SESSION_SECRET` همه را خارج می‌کند.
- هنگام کار روی همین سرور، origin protection و فایروال centimelk و سایت `reza.noorproxy.shop` را دست نزنید مگر کار صریحاً همان باشد.
